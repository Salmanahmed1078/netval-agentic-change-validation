01The problem

Configuration changes are a leading cause of network outages. Network CI/CD gates either run every test (slow, and they block 62% of correct changes) or a few fixed rules (they miss side effects). Neither knows what a change is meant to do.

02Research gap

  1. No comparison with a fixed CI suite on the same changes.
  2. False approvals of an LLM gate are not measured.
  3. Effect of ticket quality is unknown.

03Method: the NetVal gate

  • The twin finds what changed: every flow, route, adjacency and load shift.
  • The LLM only labels each difference: intended, unintended or unsure.
  • Plain code decides; missing intent means ESCALATE, never a guess.

07Conclusion

A digital twin that computes what changed, plus an LLM that judges only whether the ticket explains it, gives a CI gate that is safer and 8.6× faster than running every test, costs about US$0.015 per PR, gives the same verdict across runs (κ = 0.92) and fails safe when intent is missing.

Limits: our own Python twin, synthetic changes and modelled CI time. Next: real Batfish + containerlab, larger local models and real change tickets.
